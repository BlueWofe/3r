# 官網 UI／UX 改版

## 方向與範圍

參考使用者提供的 `code_artifact.html`、`code_artifact (1).html` 與 [iM Church](https://www.im-church.org/)，採明亮、親切的米白／深綠／暖金設計。附件僅作設計與文案參考，範例人員、成效、成立年份、收款帳號、扣稅資格與收據承諾均不視為正式資料。

首頁採大幅主視覺、簡短宗旨、四個服務入口、經文與三篇最新消息／見證；文章保留日期、作者與全文連結。照片需為協會提供或後台發布的公開媒體；沒有照片時使用既有插畫，不能把示意圖說成真實事工紀錄。保留既有工作台入口、去背頁尾 Logo、產品圖片高度限制及展示用途。

所有公開頁使用同一字級、間距、按鈕、頁首與卡片規則，手機改為單欄、至少 44px 操作目標。調整限制在前台樣式，不重做既有後台操作或權限。

## 奉獻

桌機左側為事工意義與三個支持用途，右側為清楚的分步操作：用途、預設金額（500／1,000／2,000／5,000）或自訂金額、確認、模擬結果。手機將操作面板置前，介紹與經文隨後呈現。沿用 donations API，僅單筆模擬；每月奉獻、匯款及劃撥標示待開通，提供聯絡協會入口，不展示範例帳號或收據申請。匿名訪客能閱讀所有介紹，建立個人模擬紀錄時需登入。介面就緒後才開放輸入，處理中鎖定重複提交；回應成功後才顯示結果；成功／失敗／取消用中文標示。

## 協會介紹、架構與人員

頁面頂端以錨點導覽連到宗旨、沿革、組織與同工。既有 CMS 本文完整保留，增加易讀的層級架構與人物卡片。公開資料來源為已發布 `organization` 頁面；可選 `metadata.organization_levels`（文字陣列）、`metadata.departments`（name／description）、`metadata.team`（name／role／bio）資料。後台該頁提供中文結構欄位，保留其他 metadata。無結構資料時呈現明確的「示範架構／同工介紹版型，待正式資料確認」，使用職務範例而不虛構人名；正式發布空陣列可移除範例。

團隊照片可先以公開頁面圖片與本文圖片呈現；人物卡片沒有照片時使用中性圖示。不要使用私人會員或個案 API 作公開名冊。

## 經文與照片

設立共用經文區塊，首頁及奉獻頁使用「若有人在基督裡，他就是新造的人，舊事已過，都變成新的了。」— 哥林多後書 5:17（和合本）。顯示完整出處，不跑馬燈、不截掉手機文字。

建議首批 6–10 張：一張寬幅主視覺、四張服務照片、一張團隊合照、二至四張食品與製作照片；涉及服務對象的照片須經協會確認可公開。從現有 about 公開封面／已發布文章封面導入圖文區；缺圖使用插畫。後台已可上傳公開封面與本文圖片。

## 套件

本輪沿用 Vue 元件、原生表單與 CSS Grid／Flex，整理共用設計 token。附件的 Tailwind CDN、Lucide CDN、inline onclick 不直接搬進產品。Bootstrap JavaScript 的 DOM 行為與 Vue 可能衝突，參見 [官方說明](https://getbootstrap.com/docs/5.3/getting-started/javascript/)；若之後大量擴充複雜互動元件，再評估 [Nuxt UI](https://ui.nuxt.com/)／Reka UI，避免為單次樣式改版導入全域 reset。

## 分工與驗收

- Astra：設計規則、資料約定、整合、視覺檢查及 dev／獨立 UAT 發布。
- Terra：前台共用樣式、首頁、奉獻、協會介紹、經文元件與組織資料編輯。独立工作目錄與分支提交。
- Luna：公開導覽、已登入入口、奉獻三種結果與防重複送出、架構／人物資料、草稿不公開、320／390／768／1440px 溢出與頁面截圖。獨立工作目錄；不自行部署或重置共享資料庫。

以現有 API 契約為準；不修改金流或資料權限。建置、型別檢查、核心工作台與圖片規則回歸通過後，發布 r3-uat 並核對既有 py 服務。
