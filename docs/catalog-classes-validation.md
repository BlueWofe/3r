## 核心案例

產品驗證涵蓋多規格、價格小數、重複規格、階梯價格／數量門檻、未發布與停用商品、庫存不足、公開圖片限制，以及一般內容 API 無法繞過產品驗證。瀏覽器實際新增與編輯兩組規格及大量優惠。

班別驗證涵蓋每週、月底 31 日、第五及最後一個星期、起迄日期、當日已結束時段、重複生成、資料庫唯一鍵、既有場次異動保留、每日新增遠端日期、停用班別、無效老師、衝突、缺額指派與權限／版本檢查。

日期範圍包含今天至第 90 天（起迄兩端皆含），並由班別結束日裁切。月份不存在的日期不產生場次；`skipped` 用於已結束時段、老師無效、衝突等可辨識場次。編輯同一規則保留 ID；刪除後新增視為新規則，不會撤銷舊場次。既有場次需從排課管理異動。

UI 識別碼改用 HTTP UAT 也可用的 `crypto.getRandomValues`；報價在變更規格／數量後失效，忽略較舊回應。產品儲存防重複點擊，圖片集最多 10 張。

外網測試發現登入畫面可能在客戶端程式尚未載入前送出原生表單。登入欄位及送出在掛載完成前保持停用，並在請求中防重複送出；新增測試刻意延遲 JavaScript 下載驗證此行為。

## 環境隔離

UAT 使用 py VM 上既有的獨立 `r3-uat` Compose project 與 TCP 3180。部署腳本會先備份 3r，再更新 3r 容器並核對 py 容器識別及健康；不操作 py 的資料庫或持久目錄。帳號及密碼以環境外的私人操作流程設定，不納入 Git。
