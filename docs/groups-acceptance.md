# 小組與文章分類驗收操作

## 執行前提

使用整合環境的 Compose 服務，確認 API、前台與背景 worker 已就緒。E2E 帳號由專案合成資料建立，執行時需設定 `DEMO_PASSWORD`；可用 `BASE_URL` 指定測試站，預設為 `http://localhost:3180`。不要使用正式帳號、正式 LINE token 或真實收款服務。小組群發只寫入 mock LINE 記錄與站內通知，不會對外傳送。

```powershell
$env:DEMO_PASSWORD = '<合成帳號密碼>'
npm exec playwright -- test --list
npm exec playwright -- test tests/e2e/groups*.spec.ts
```

在共享 UAT 執行前，先確認目前版本已完成部署與遷移；不要 reset 資料庫或重建既有帳號。先用 `--list` 檢查套件發現，再由整合負責人安排實際測試，避免不同人同時修改同一批測試資料。

## 驗收重點

- 管理者建立唯一名稱的小組、加入合成會員、確認重複會員 ID 會去重，更新版本後舊版本寫入回 409。一般會員只能取得自己的小組選項，不能列出名冊或管理小組。
- 對外最新消息、文章詳情、首頁與搜尋不顯示小組限定消息，即使已登入也相同。公開文章分類和主題篩選互相獨立；舊的「見證分享」分類仍能辨識為生命見證。
- 成員可在「小組消息」讀取有效小組的已發布文章。移出成員或停用小組後，下一次請求即失去文章權限；草稿與尚未發布文章不可見。
- 群發收件人是所選有效小組會員的聯集，跨組重複會員只收到一次。同一內容版本再次群發應回傳同一筆紀錄；過期版本、零收件人及群組文章圖片應被拒絕。通知只包含通用提示與文章連結，不複製私人標題或內文。
- 會議與資源需先通過本身的讀取授權，再檢查群組／角色對象。資源附件 URL 需獨立重新授權；透過範圍較寬的會議不得讀取另一範圍的私人附件。改變資源群組範圍後，舊成員立即失去下載權限，新成員依新範圍取得權限；更新時省略 `group_ids` 應保留既有範圍。
- 手機與桌面管理員可建立小組、調整成員、選取文章所屬小組並群發；一般會員可瀏覽小組消息清單與詳情，但看不到管理入口。頁首 Logo 可返回前台，且不應出現獨立的「回到官網」文字按鈕。

## 測試資料與清理

測試建立的文章、小組、會議、資源及檔案名稱需帶唯一後綴。完成後刪除測試文章、會議及資源；小組採停用並清空會員，不能刪除。若測試需要新合成帳號，使用不與種子帳號重複的電話，測後保持停用。群發與稽核歷史是不可逆的驗收記錄，應透過唯一文章 ID 區隔，不嘗試刪除或覆寫。測試不可變更種子使用者角色，也不可直接呼叫資料庫重置。
