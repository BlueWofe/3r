Product carousel acceptance — 2026-10-16 (Asia/Taipei)

Scope: user-requested product image interaction, without backend/schema/data changes.
Preview: http://127.0.0.1:3184 (Terra worktree; final implementation includes fresh-touch click guard and explicit dialog keyboard focus trap).

All browser /api/v1 requests are fulfilled with synthetic fixtures. Images are local SVG responses. Product detail is entered through client navigation to avoid SSR bypass of browser interception. No live account is used, no order is sent, and no database is seeded/reset. Homepage SSR may perform existing public read-only requests.

Coverage:
- Additional thumbnails select the main photo; previous/next wrap across all photos and counter stays synchronized.
- Clicking opens the selected photo in a modal; arrows and keyboard Left/Right stay synchronized with the main gallery.
- Tab/Shift+Tab stay inside the modal; Escape and close button restore opener focus and prior body overflow and scroll offset.
- Navigating away while modal is open restores scrolling; returning starts with the main image and no modal.
- A genuine mobile tap opens the modal. Chromium CDP trusted touch gestures exercise horizontal forward/back swipes and vertical non-navigation both inside the modal and on the main gallery; swiping the main image does not accidentally open the modal.
- Single-photo, zero-photo illustration, duplicate IDs, and missing-primary-photo promotion retain sensible behavior.
- Existing layout protection retained: 0/1/3/10 supporting photos at 320/390/1440 widths; thumbnails below main image, three supporting photos share one row, bounded heights, product information stays in its responsive column, no horizontal overflow, no download links, selected-state thumbnail buttons keep image height.
- Existing quote/cart assertions and mocked public story/article/food/guest-order workflow remain enabled.

Browser coverage: desktop Chromium and mobile WebKit. WebKit exposes no CDP session, so the trusted-touch case uses a separate Chromium mobile 390x844/hasTouch context. Desktop touch-case duplication is intentionally skipped; desktop uses accessible buttons and keyboard. This is browser emulation, not a physical iPhone acceptance test.

Testing found and Terra fixed explicit focus trapping and allowing a new touch gesture after a prior swipe. Chromium can omit its compatibility click when Playwright touchscreen.tap immediately follows injected CDP gestures, even though trusted touchstart/end arrive; the trusted-touch case starts with the actual tap and then tests both gesture surfaces without mixing the input sources in that order. No arbitrary sleep or deleted gesture assertion was used to pass the test.
