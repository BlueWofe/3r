# 3R 平台操作與驗收指南

## 驗收前準備

1. 準備 Docker Compose、Node.js 22，並確認 3180 port 未被占用。
2. 在未納入版本控制的 `.env` 設定 `DEMO_PASSWORD` 與 `DEMO_SEED=true`。密碼請使用本機或 CI 專用值，勿重用正式密碼。
3. 啟動服務並建立合成資料：

   ```sh
   docker compose up -d --build
   docker compose exec -T backend php artisan migrate --seed --force
   ```

4. 開啟 <http://localhost:3180>，確認公開首頁可載入。測試帳號為 `0900000001` 管理員兼教師、`0900000002` 及 `0900000004` 教師、`0900000003` 會友、`0900000005` 內容管理員；密碼均為 `DEMO_PASSWORD`。
5. 不可將測試連到含真實個資或正式捐款資料的資料庫。所有付款、通知及整合測試都應維持 mock 模式。

## 自動驗收

```sh
npm ci
npx playwright install --with-deps chromium webkit
npm run test:e2e
```

測試包含伺服器端 own/all 權限、排程請假與邀請接受、管理員換人、取消課程禁止點名、舊版本衝突、公開內容、表單、mock 捐款，以及桌機/手機公開首頁、登入與行事曆。測試資料使用唯一名稱，排程日期相對於執行日建立。失敗時查看 `playwright-report/`、`test-results/` 和 `docker compose logs`。

## 人工驗收

- 用訪客瀏覽首頁、公開內容與商品；確認內容有「示範」標示，搜尋與頁面導覽可用。
- 以管理員登入，建立未來日期的排程並指派教師；以教師帳號查看自己的排程並提出請假，再以管理員邀請其他教師補位，最後確認邀請接受及管理員換人紀錄。
- 確認會友帳號無法讀取全體使用者或建立排程；管理員可檢視全體排程與角色。
- 取消一筆測試排程後確認不能登錄出席；嘗試以過期版本儲存並確認系統拒絕覆寫。
- 建立一筆發布表單並提交合成回覆；建立一筆模擬捐款並重播處理，確認沒有重複入帳。
- 在手機寬度檢查公開首頁、登入與行事曆，確認主要操作可見且頁面沒有水平溢出。

## 外部環境與目前限制

目前尚未連接正式 GCP SSH 部署環境；SSH 主機、金鑰與部署權限待管理方提供並設定。簡訊、LINE、Google Drive 與支付服務供應商 API 尚未完成正式憑證設定與端到端驗證。驗收只涵蓋合成資料和 mock 行為，不能視為正式上線、正式通知或真實金流驗收。
